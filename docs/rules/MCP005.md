# MCP005: Potential data exfiltration path

**Severity:** Critical for unrestricted network sinks; High for constrained external sinks

## What it detects

A sensitive source tool and an external sink tool registered to the same MCP context. The path is modeled as source to agent context to sink.

## Why it matters

Data returned by one tool can be placed into a later tool call by an MCP client, creating a cross-tool exfiltration capability even when neither tool is independently a vulnerability.

## Vulnerable example

```text
read_payroll -> agent_context -> post_webhook
financial       shared context   unrestricted URL
```

## Safe example

A read-only server with no external sink, or separate MCP registration contexts for sensitive reads and external actions.

## Remediation

Constrain destinations, require approval, minimize returned data, and separate sensitive source tools from external sink tools.

## Limitations

This is a capability path, not proven runtime data flow. Ruleset 0.1 isolates source modules and MCP registration objects to avoid cross-server paths, which may miss servers assembled dynamically across modules.
